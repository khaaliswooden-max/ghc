\section{Implementation}
\label{sec:impl}

The GHC reference implementation is co-designed with this paper. Code
artifacts referenced below are reproducible from the GHC repository.

\paragraph{Proofs.}
\path{proofs/} contains the kernel Lean~4 \cite{lean4} formalization
in pure Lean 4 (no \texttt{mathlib} dependency); 20-second builds.
\path{proofs-mathlib/} contains the Phase B+ extensions on top of
mathlib4 \cite{mathlib4} (density-matrix purity, charpoly under
relabel, Chebyshev/Chernoff audit concentration, exponential channel
survival). Both trees are gated by CI to contain zero \texttt{sorry}s
and zero unsafe \texttt{axiom}s.

\paragraph{Core (Rust).}
The \path{core/} workspace ships four crates that are runtime mirrors
of the proven theorems, with property tests (\texttt{proptest}) that
re-establish each Lean invariant in Rust so that any drift between
formalization and runtime breaks the build:

\begin{itemize}
\item \texttt{ghc-algebra}: \texttt{Verdict} lattice (mirroring
  \texttt{Ghc.Verdict}), \texttt{Process} + \texttt{halal\_closure}
  (\texttt{Ghc.Process}), \texttt{Batch} + \texttt{Contribution}
  (\texttt{Ghc.Quantum.Batch}), deterministic and stochastic channels
  (\texttt{Ghc.Info} and \texttt{GhcMathlib.Channel}), and audit
  \texttt{plurality} (\texttt{Ghc.Convergence}). 29 unit and property
  tests.
\item \texttt{ghc-graph}: \texttt{ProvenanceDag} with
  \texttt{weight\_seq} / \texttt{count\_weight} / \texttt{total\_weight}
  (mirroring \texttt{Spectral.Graph}); \texttt{fingerprint} computes
  the top-$k$ eigenvalues of the normalized weighted Laplacian via
  \texttt{nalgebra::SymmetricEigen}. 5 tests including bijective
  spectral invariance.
\item \texttt{ghc-zk}: zk-Halal Groth16 over BLS12-381 via arkworks
  \cite{arkworks}. The \texttt{HalalThresholdCircuit} encodes
  (i)~domain check $w_i (w_i - 1)(w_i - 2) = 0$ forcing
  $w_i \in \{\halal, \mashbuh, \haram\}$, (ii)~threshold check
  ($w_i = 0$ for \halal-only, $w_i (w_i - 1) = 0$ for $\leq \mashbuh$),
  and (iii)~a Poseidon binding commitment
  $c = \mathsf{Poseidon}(\mathrm{salt} \,\Vert\, w_0 \,\Vert\, \dotsb
  \,\Vert\, w_{n-1})$ on BLS12-381 (width 3, $\alpha = 17$, 8 full +
  29 partial rounds), via \texttt{ark-crypto-primitives}. 8 tests
  including hostile-witness rejection and a
  \texttt{native\_and\_circuit\_poseidon\_agree} equality check that
  guarantees the off-circuit commit() and the in-circuit
  \texttt{PoseidonSpongeVar} produce byte-identical outputs.
\item \texttt{ghc-cli}: the \texttt{ghc} binary surfaces
  \texttt{closure}, \texttt{plurality}, \texttt{fingerprint},
  \texttt{prove}, \texttt{verify}, and an end-to-end \texttt{demo}.
\end{itemize}

\paragraph{Reference benchmarks.} On a stock x86\_64 Linux runner,
the v0.0.x \texttt{HalalThresholdCircuit} with $n = 3$ and
Poseidon-on-BLS12-381 commitment produces a 192-byte Groth16 proof
(release build):

\begin{center}
\begin{tabular}{lr}
\toprule
Operation & Wall time \\
\midrule
\texttt{Groth16::circuit\_specific\_setup} & 57 ms \\
\texttt{Groth16::prove}                    & 54 ms \\
\texttt{Groth16::verify}                   & 2.3 ms \\
\bottomrule
\end{tabular}
\end{center}

CI invokes \texttt{cargo run -{}-release -p ghc-cli -{}- demo} on
every push; a green build is the canonical operational
reproducibility certificate.

\paragraph{Services (Python).}
\path{services/ghc_api} is a FastAPI gateway exposing the
authority registry, certificate lookup/search, bidirectional
EPCIS translation, and the ML inference endpoints below.
\path{services/ghc_traceability} ships the real EPCIS 2.0
$\leftrightarrow$ GHC mapping, covering \texttt{ObjectEvent},
\texttt{TransformationEvent}, and \texttt{AggregationEvent}, with
roundtrip pytests under \path{services/tests/}.
\path{services/ghc_ml} hosts two trainable models, both
implemented in PyTorch and trainable on CPU in seconds on
synthetic data so CI keeps full coverage:
\begin{itemize}
\item \texttt{IngredientClassifier} — corpus arm
  (haram-keywords + curated E-number lattice) plus a small
  character n-gram MLP fallback for novel strings. The neural
  arm converges to $>$~0.9 validation accuracy on
  \path{ghc_ml.data.synthetic.synthetic_ingredients}; the
  corpus arm guarantees correct classification for known
  E-numbers (e.g.\ E120 $\to$ ḥarām, E322 $\to$ mashbūh) and
  known haram tokens (pork, lard, alcohol). Phase E+ swaps the
  fallback for LayoutLMv3 \cite{layoutlm} + multilingual XLM-R
  for image-based label OCR.
\item \texttt{SupplyChainRiskGNN} — two-layer message-passing GNN
  (custom implementation, no
  \texttt{torch\_geometric} dependency) over per-node
  $(d_{\rm in}, d_{\rm out}, \log(1 + w_{\rm in}),
  \log(1 + w_{\rm out}))$ features and edge-weight-modulated
  messages, with a mean-pool readout and a sigmoid head emitting
  a scalar risk in $[0, 1]$. Trains to validation MAE $<$ 0.20
  and PR-AUC $>$ 0.3 on synthetic provenance DAGs whose
  ground-truth risk is computed deterministically from edge
  count and weight statistics.
\end{itemize}
Both models surface as \texttt{POST /v1/ml/ingredient} and
\texttt{POST /v1/ml/risk}; their lazy-load fixtures train the
default models with seeded determinism on first request.

\paragraph{Spec.}
\path{spec/} publishes the GHC Protocol as Markdown plus JSON Schema +
JSON-LD contexts. The data model extends EPCIS~2.0 \cite{epcis2} and
W3C PROV-O \cite{provo}; attestations are W3C Verifiable Credentials
\cite{vc}. The \texttt{ghc-cli} \texttt{prove} / \texttt{verify}
subcommands produce/consume the binary serialization that the v0.1
spec will wrap in a VC envelope.

\paragraph{Integrations.}
\path{integrations/certifiers/} ships a \texttt{CertifierAdapter}
abstraction with two concrete realizations: \texttt{FixtureCertifier-
Adapter} (JSON-fixture-backed; used in CI and offline development)
and \texttt{HttpCertifierAdapter} (reusable scaffold for
documented REST APIs). The default registry (\texttt{REGISTRY})
binds JAKIM, MUI/BPJPH, HFA, ESMA, SFDA, and SMIIC each to a
fixture-backed adapter; production deployments override
\texttt{REGISTRY} at startup with HTTP-backed adapters subject to
each registry's terms of service.

\path{integrations/dlt/evm/} ships the EVM-side ZK pipeline: a
Circom \cite{circom} port of the \texttt{HalalThresholdCircuit}
compiling to BN254 (alt\_bn128), a \texttt{snarkjs}-generated
Solidity Groth16 verifier deployable to any EVM L2, and an
end-to-end assertion suite (\texttt{scripts/test.sh}).

\path{integrations/dlt/fabric/chaincode/} ships the Hyperledger
Fabric \cite{fabric} chaincode in Go: an \texttt{Attestation}
record keyed by Poseidon commitment, with operations \texttt{Attest},
\texttt{Get}, \texttt{Exists}, and \texttt{ListByIssuer}, and
field-level validation that gates on the closed set of
\texttt{ghc:scheme} tags from \Cref{sec:zkhalal} and on the
verdict alphabet from \Cref{sec:hcf}. Nine \texttt{go test} unit
tests cover the success path, duplicate rejection, and every
validation failure mode.
